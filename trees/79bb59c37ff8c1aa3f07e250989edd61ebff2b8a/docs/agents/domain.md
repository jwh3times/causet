# Domain docs

This repository uses a single context.

## Before exploring

Read [product intent](../product.md), [architecture](../architecture.md),
and relevant decisions from [the ADR index](../adr/README.md).

Read `docs/CONTEXT.md` when present. This is the repository's glossary
location, adapting the skills' root `CONTEXT.md` convention to the
documentation layout required by AGENTS.md.

If the glossary is absent, proceed silently. Use the domain-modeling
skill to create it lazily when a domain term is resolved.

## Recording terms and decisions

Keep the glossary in `docs/CONTEXT.md` and decisions in `docs/adr/`.
Use glossary terms consistently in issues, proposals, and tests.
Keep implementation details out of the glossary.

If a proposal conflicts with an existing ADR, identify the ADR and
explain why its decision should be revisited.
